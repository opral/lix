## Performance evidence

These are native debug measurements from reviewer probes of the parser modules.
They exclude the Wasm host, Lix SQL execution, and storage, and are diagnostic
samples rather than statistical benchmark claims or CI timing thresholds.

| Shape | Before | After |
| --- | ---: | ---: |
| `"*a ".repeat(4000) + "a\n"` | 1,096 ms | 22 ms |
| `"[".repeat(4000) + "a\n"` | 219 ms | 21 ms |
| 20 recursive `"[" + source + "](u)"` wrappers | 1,240 ms | 0.72 ms |
| 400 recursive link wrappers | 5,820 ms, accepted | 13.3 ms, explicit nesting-limit error |
| 1,000 nested blockquotes | process stack overflow | explicit nesting-limit error |

Nested subtree signatures previously re-escaped descendant JSON strings. The
exact old encoding grew to approximately 35.7 MB at 20 blockquote levels. The flat
encoding produced a roughly 15 KB signature at depth 500 in an isolated tree probe;
the public parser now rejects excessive recursive depth before it exhausts the
host stack.

## Behavioral contract

Accepted source bytes remain necessary for reconstructing noncanonical spelling
from exported semantic rows. A Lix snapshot includes those bytes; semantic rows
alone are not a standalone lexical archive. Unedited files retain their bytes,
and edits preserve unaffected source spelling when its meaning stays valid.

General/formatted row edits and row-only serialization are reparsed and compared
semantically before acceptance. Safe literal-prose edits retain their fast path.
Unrepresentable edits return an error instead of silently changing content.
Examples include inconsistent table header roles, HTML rows that become plain
paragraphs, and inline code values containing line endings.

The parser and row graph enforce a nesting budget of 64. See the plugin README
for payload shapes, coordinated structural edits, and SQL examples.
